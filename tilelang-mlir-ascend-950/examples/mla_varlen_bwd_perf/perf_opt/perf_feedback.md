# 性能反馈（[DESIGN_LIMIT]）

## 触发判定

- **设计层归因**：剩余缺口归因到 DESIGN.md 的两处设计层假设，而不是 tiling/参数：
  1. `DESIGN.md` §1.6.0「设计期 roofline（D-2）」把**每迭代单价当作与 request 长度无关的常数**
     `2.97–3.19 µs/迭代`（来源：dense 生产实测 2.97 + 本轮 packed 探针 3.19），并用它线性投影三个 workload
     （mixed 400.0–429.5 ms、8x4k 152.9–164.3 ms、kimi 150.6–161.8 ms）；
  2. 同节 R3「每 query 行 L1 填充次数」（Nk=96 时 mixed 58.4）与 §3.3/§6.3 的查询块循环结构
     （每迭代只装 1 个 64 行查询块的 q/do，`q_s/do_s` 单版本、`num_stages` 上限受 L1 版本压力约束）
     决定了填充的工作集与复用距离，从而决定该单价能否成立。

  Stage 4 已把参数层穷尽：`num_stages` 1/2/3/4/5 全扫（3 为拐点，4/5 回退）、操作数布局两种
  （转置副本 / 自然 (K,N)，后者把填充字节与描述符各减半）、以及 `block_n/block_m/head_slab`
  受三 launch 契约与 grid-slab 断言冻结不动。所有留在冻结结构内的组合最好到 mixed 563.7 ms（−18.2%）。
- **实测与假设矛盾**：§1.6.0 的「单价常数」假设被平台实测直接推翻——单价随 request 长度分层，
  同构对照下 len≤5376 为 3.11–3.14 µs/迭代、len=16384 为 4.26 µs/迭代（+37%），
  且逐迭代 AIC 管道工作量在两种长度下**完全相同**。因此 mixed 的 400–430 ms 投影在冻结结构内不可达
  （实测 563.7 ms，是投影上界的 1.31×）。注意：DESIGN §8.4 的「必达」档（mixed ≥2.8× ⇒ ≤616 ms）
  已达成（实测 3.07×）；被推翻的是「预期」档所依赖的单价常数假设。

## 参照锚定

- **参照实现**：同族最近参照 `examples/mla_dense_bwd/_bwd_kernel`（与本 kernel 同一 5-GEMM 显式 L0 结构、
  同一 epilogue/写回，仅 extent 为静态、q 布局为 dense），其生产实测为 **2.97 µs/迭代**（S=2048，H=8，
  22 016 块，`evidence/msprof_pipe_capture1.csv`）。平台知识库检索（`kb_search`）中与本现象相关的条目为
  `CASE-batch2-mla-varlen-reuse`（本算子的同源复用案例）与 `CONST-950-gemm-mte2-burst`
  （MTE2 有效带宽随 DMA 段长变化：128 B → 101–105 GB/s/核，HBM 有效 1.42–1.48 TB/s），
  **没有** 关于「packed 长 request 的填充单价」的条目。
- **不可移植论证**（逐条）：
  1. dense 参照的静态 extent 只在 S=2048–8192、每 (b,h) 独立切片的几何下测过，**从未覆盖 packed 的
     16384 长度区间**；本 kernel 在 len≤5376 已与它同量级（3.11–3.14 vs 2.97），说明结构本身没有落后，
     落后只出现在参照未覆盖的长度区间 ⇒ 参照不能证明该区间存在更优的冻结结构。
  2. 平台知识库无可移植的替代形态条目（见上），故**未找到在 len=16384 packed 区间实测更优的同族参照，
     本反馈的天花板结论置信度降级**（只对「本冻结结构 + 本工具链」成立）。
  3. DESIGN §1.6.0 R3/R4 淘汰 query-stationary（GM +55%）、两 kernel 拆分（FLOPs ×2）、物化 P/dS
     （46 GB/张量）的理由是**设计期推算，本轮未实测**，按未实证假设记录，不用作否决依据。

## 假设

`DESIGN.md` §1.6.0「设计期 roofline（D-2）」：

> 单价（per-iteration，单核）`2.97 µs`（dense 生产实测）/ `3.19 µs`（本轮 packed 探针，保守上界）；
> `全量 = 单价 × iters / 28`；投影 mixed 400.0–429.5 ms、8x4k 152.9–164.3 ms、kimi 150.6–161.8 ms。

即：*每迭代的墙钟代价与 request 长度、packed 长度分布无关*，可乘以迭代数线性外推。
配套的结构假设在 §3.3/§6.3：每迭代只装 1 个 64 行查询块，`num_stages=2`（该节已注明只有 `qT_s` 拿到双版本）。

## 实测

口径：任务平台 `msopprof` kernel `Task Duration(us)`，`T_op` = 一次调用内全部 launch 求和
（原始采集 `perf_opt/profiles/`，逐行记录 `perf_opt/perf_records.jsonl`）。

**A. 单价与 request 长度（同构对照，排除异质/派发因素）**

| case（同构 = 所有 request 等长） | iterations | stages=2 `T_op` | stages=2 us/it | stages=3 us/it |
|---|---:|---:|---:|---:|
| 6×5376（token 数与 mixed 相同） | 1 849 344 | 259 517.2 µs | 3.830 | **3.108** |
| 8×4096（benchmark） | 1 441 792 | 203 983.0 µs | 3.832 | **3.144** |
| 1×16384（单个长请求） | 2 818 048 | 529 639.6 µs | **5.230** | **4.264** |
| mixed（benchmark，16384 主导） | 3 770 496 | 689 184.2 µs | 5.069 | 4.138 |

同一 iteration 定义（DESIGN §1.6.0 R3 公式复算）、同一 tile、同一 pipeline 设置下，
单价在 3.11 与 4.26 之间分层 ⇒ §1.6.0 的单价常数假设不成立。

**B. 逐迭代管道工作量与长度无关**（把 sum 口径 share 乘 `us/it`）：

| workload | mad | mte1 | mte2 | fixpipe | 管道和 | us/it |
|---|---:|---:|---:|---:|---:|---:|
| 8x4k（stages=2） | 0.80 | 0.73 | 1.18 | 0.62 | 3.44 | 3.832 |
| mixed（stages=2） | 1.08 | 0.99 | 1.57 | 0.86 | 4.64 | 5.069 |

即 5 GEMM + 2 段向量 + 1 次原子 store 的**工作量相同**，差的是每迭代被拉长的比例（各管道同幅上升），
而不是多做了一份工作。

**C. 不是派发/长尾，也不是 L2 footprint**

- 逐核累计工作量（按 `block_id` 汇总每块 `aic_time`）：max/mean = 1.004（8x4k）/ 1.007（mixed）/ 1.006（kimi）
  ⇒ 硬件动态派发已把每核负载抹平，设计 §5.5「逻辑块超发 + 动态派发压长尾」**成立**，长尾不是缺口来源。
- `1×16384, H=16`（并发 head footprint 降 8×）：5.105 µs/it vs H=128 的 5.230 ⇒ 与 footprint 无关；
  L2 读命中率 8x4k 64.4% / mixed 59.4% / 6×5376 61.7% / 1×16384 54.9%，无量级差。

**D. 冻结结构内的参数层已到拐点**（8x4k / mixed `T_op`，µs）：

| 变体 | 8x4k-bf16 | mixed-bf16 |
|---|---:|---:|
| baseline（stages=2） | 203 983.0 | 689 184.2 |
| stages=3（采纳） | **168 556.1** | **563 712.1** |
| stages=4 | 172 179.4 | 574 108.5 |
| stages=5（+自然操作数） | 176 003.8 | 593 154.5 |
| 自然 (K,N) 操作数（填充 −50%） | 191 626.6 | 644 264.2 |

**E. 剩余缺口的量级**：mixed 519–564 ms 区间需要再降 13%（564 → 500），
对应 us/it 4.14 → 3.66，即要消掉「长度分层」带来的一半左右；按 B/C 的证据，
这只能来自填充粒度或工作集驻留的结构改动（更大的查询块填充/两遍 query 切分/静态 extent 分桶多次 launch），
都属于任务映射或 §1.6.0 R3 的算法层选择，不在冻结结构内可解。

## 影响面

- 受影响算子族：所有「packed/varlen + key-stationary + 每迭代只装一个查询块」的 attention backward
  （`mla_varlen_bwd`、`flash_attention` 反向的 packed 形态），以及任何把单价当常数做 roofline 投影的设计。
- 受影响 shape 范围：单 request len ≥ 8192（实测 16384 区间单价 +37%），
  对 mixed 这类「长短混合且长请求主导迭代数」的 workload 影响最大；
  纯短请求（len ≤ 5376）不受影响（已达 dense 参照同量级）。
- 若改设计：预期影响 Stage 1（§1.6.0 R3 的填充粒度/工作集驻留、§3.3 循环结构、§6.3 多缓冲）与 Stage 3
  （kernel 结构重写），Stage 4 重跑四 workload 复核；工作量约等于本 kernel 主 pass 的一次结构重构。

## 反馈结论

DESIGN §1.6.0 的「单价常数」假设被平台实测推翻（同构对照下 len≤5376 为 3.11–3.14 µs/迭代、
len=16384 为 4.26，逐迭代管道工作量相同），mixed 的 400–430 ms 投影在冻结结构内不可达
（实测 564 ms = 投影上界 1.31×，但 §8.4 的必达档 ≤616 ms 已达成）；
Stage 4 已交出冻结结构内最优版本（8x4k −17.4%、mixed −18.2%、kimi −17.7%，精度逐位不变）。
