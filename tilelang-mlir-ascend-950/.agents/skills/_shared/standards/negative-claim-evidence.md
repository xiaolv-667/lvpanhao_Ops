# 弃选论证证据规则标准 ⭐

> **单一事实源**：本文件是「负向断言举证责任 / 弃选论证证据规则」的权威版本（conductor Stage 1/2 透传文本出处）。机械核对由 `statectl gate 1`（`gate_lint.py` 规则 `S1-REF-PATHS`：引用的 `docs/`、`testing/`、`examples/` 路径逐一存在性核对）执行。

## 1. 透传文本（conductor 调度 designer / reviewer 时引用）

> §1.6.1 否决项与 §1.6.3 弃选候选的每条负向论断（API 不支持/代价高/无先例/无链支撑）必须附已亲自核对的 `docs/`、`testing/`、`examples/` 路径与具体限制条款，或显式标注「未文档化假设 + 估算依据」；弃选候选所依赖的 API 必须先枚举名字，再按任务 ruleset 在适用文档与实际语言模块中检索并核对导出、签名和版本——禁止凭先验（尤其 GPU 直觉）在检索前否决候选。

## 2. 规则要点

1. **举证责任在弃选方**：声称"API 不存在 / 不支持 / 代价高 / 无先例 / 无链支撑"的一方必须举证；无证据的负向断言标注「待确认」并列入风险点，不得作为决策依据。
2. **API 先枚举后检索**：弃选候选依赖的 API 先写出名字，再按任务 ruleset 检索适用文档与实际模块（不能用其他后端的同名导出代替当前证据）；检索不到且确需断言"不存在"的，记录查证过程。
3. **引用可核验**：所引 `docs/` / `testing/` / `examples/` 路径必须真实存在（gate_lint 机械核对）且引用具体限制条款，不得只给目录不给条款。
4. **未文档化假设显式标注**：确无文档支撑时必须写「未文档化假设 + 估算依据」，不得伪装成已验证结论。
5. **代价类论断先查实测**：先查任务平台 knowledge.patterns 与 cost_measurements 中匹配型号、版本和 workload 的实测条目；已有匹配数字不得当作未实证假设，与匹配实测矛盾即 fail。其他组合的数字只作参考，不用于直接否决当前候选。

## 3. Stage 2 前提核对要求（reviewer 维度 8）

对 §1.6.1 否决项与 §1.6.3 弃选候选的每条负向论断，**亲自打开所引 API 文档核对代价机制前提**（如 repack 是核内 UB 级还是 GM 级）；未引证或与文档矛盾 → 维度 8 fail。另须对照 pattern-library 实测条目：代价类论断与实测矛盾 → fail；未引用已有实测数据的 → 要求补证。
