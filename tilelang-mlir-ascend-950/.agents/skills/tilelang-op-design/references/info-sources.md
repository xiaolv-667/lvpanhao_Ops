# 信息收集与信息源优先级

## 1. 强制步骤 0：搜索同类实现

先读任务平台的 kernel 模板，再搜索并完整读取同类 examples/tests。核对其编译目标、语言模块与版本是否兼容本任务，然后分析 Kernel 结构、内存分配、搬运与同步。

## 2. 信息收集步骤

1. 读取当前平台兼容的同类实现。
2. 读取平台 knowledge.patterns 下的 INDEX.md，通过 kb_search 携带 --task-dir 检索命中条目。
3. 按 ruleset 查实际语言模块、API 文档、导出与定义；静态导入时确认模块文件路径。
4. 按 ruleset 核对模式与编译参数。
5. 迁移源用于解读语义、算法与硬件耦合，其 API 不自动成为目标平台 API。

## 3. 禁止行为

不凭记忆猜 API，不把其他后端的同名导出作为目标平台可用的证据。

## 4. 信息源优先级

API 存在性、签名与语义采用任务 ruleset 给出的文档和实际模块，并结合兼容示例核对；矛盾时确认模块路径、编译目标与版本，记录真实证据。静态 API 查询不分配 NPU 张量；需要执行设备代码时按 execution 启动。

性能代价优先使用匹配型号、工具链版本和 workload 的实测条目；无匹配证据时明确假设与适用边界。其他平台的实现或互联网资料只提供算法候选，不能直接建立当前 API 可用性或性能结论。算法调研流程继续见 [algorithm-research.md](algorithm-research.md)。
